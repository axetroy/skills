# 12 — 合同与第三方

## 目的

检查项目面向用户的合同及第三方（SDK、服务商、数据接收方）安排是否符合中国大陆法律要求。

## 适用法律

- 《个人信息保护法》(PIPL) — 第 20–23 条（共同处理、委托处理、向第三方提供）、第 39 条（出境告知 + 单独同意）、第 21 条（处理协议）。
- 《网络安全法》《数据安全法》— 运营者与处理者的安全义务。
- 《民法典》— 合同成立、格式条款规则，第 496–498 条（格式条款的公平性与可说明义务、不合理免责条款无效）。
- 《消费者权益保护法》第 26–27 条 — 不公平格式条款（排除消费者权利、加重消费者责任）。
- 《电子商务法》— 平台协议与规则。
- 《移动互联网应用程序信息服务管理规定》— App 提供者义务。

## 关键要求

1. **用户协议 / 服务协议**：须为公平的格式条款，不得免除经营者责任、不合理限制用户权利、遗漏法定义务（民法典第 496–498 条；消费者权益保护法第 26 条）。
2. **隐私政策**：见参考 02 — 须展示、可理解、与实际操作一致。
3. **第三方 SDK / 服务商**：
   - 识别每个接收数据的 SDK 与服务商。
   - 判定法律关系：共同处理（共同处理）、委托处理（委托处理）还是向第三方提供（向第三方提供）——三者对应的同意/协议义务不同（PIPL 第 20–23 条）。
   - 向第三方提供：告知用户（接收方、目的、数据种类），法律要求时取得单独同意（第 23 条）。
   - 与第三方签订数据处理协议（DPA）。
4. **境外接收方**：与境外接收方的协议加上合法出境路径（参考 03）；告知与同意（PIPL 第 39 条）。
5. **App 披露**：大陆应用商店要求披露 SDK 清单及收集数据（SDK 收集个人信息清单）。
6. **开源归属**：第三方声明（参考 08）。
7. **平台规则**：若项目托管第三方经营者/卖家，适用平台规则、准入审核与投诉处理（参考 05、09）。

## 审查要点

- 列出所有第三方 SDK 及其数据流（来自扫描）。
- 是否有用户协议？免责条款是否公平、看似可执行（未整体免除经营者法律责任）？
- 是否与每个第三方数据接收方签订 DPA？
- 向第三方提供用户数据是否披露并取得单独同意？
- 隐私政策/App 披露中是否有第三方（SDK）清单？
- 合同是否覆盖数据主体权利（删除请求转发给接收方）？

## 红旗

- **高**: 用户协议含违反消费者权益保护法第 26 条条款（如"概不负责"、"一律不退"、无理由终止账号）。
- **高**: 未取得同意且未披露即向第三方共享用户数据。
- **高**: SDK 未经合法路径及协议即向境外传输数据。
- **中**: 与接收数据的第三方无 DPA。
- **中**: 隐私政策未列 SDK 及收集数据。
- **中**: 无将数据主体删除请求转发给第三方的机制。

## 评估说明

- 判断第三方是共同控制者、委托处理者还是接收方属于法律定性；事实不清时并列说明不同定性下的义务差异，而非单方面下结论。
