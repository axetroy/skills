# 风险定级

## 目的

统一合规审查中每项发现的定级方式，使发现可比较、可排序。

## 定级模型

每项发现包含**严重程度**（若发生的影响）与**可能性**（违规目前存在或将要发生的概率）。最终定级由二者结合，严重程度主导优先级排序。

### 严重程度（影响）

| 级别 | 标签 | 含义                                                                                                                                               |
| ---- | ---- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| P0   | 严重 | 可能导致业务停摆的违规：许可缺失（无版号运营游戏、境内托管未 ICP 备案、未算法/生成式 AI 备案）、大规模违法出境、敏感个人信息未取得同意、涉刑风险。 |
| P1   | 高   | 严重的民事/行政风险：PIPL/DSL/CSL 违规很可能引发执法（罚款、责令整改、App 下架）、隐私政策与实际行为重大不符、不公平格式条款、未成年人保护违规。   |
| P2   | 中   | 中等风险：必备文件缺失（DPA、PIA）、披露不完整、缺未成年人模式、日志留存不足、被商店审核或主管部门点名但非致命。                                   |
| P3   | 低   | 轻微卫生问题：措辞瑕疵、缺第三方声明、需确认的未验证项。                                                                                           |
| P4   | 提示 | 提示性信息、良好实践，或需随法律演进而关注的事项。                                                                                                 |

### 可能性

| 级别     | 含义                             |
| -------- | -------------------------------- |
| 确定     | 已审查材料/代码中明确存在违规。  |
| 很可能   | 有强烈迹象指向违规；需少量确认。 |
| 可能     | 情形使违规合理存在；未确认。     |
| 不太可能 | 迹象表明合规；残余风险低。       |

## 组合定级表

|          | P0    | P1    | P2    | P3    |
| -------- | ----- | ----- | ----- | ----- |
| 确定     | P0    | P1    | P2    | P3    |
| 很可能   | P0    | P1    | P2    | P3    |
| 可能     | P1    | P1-P2 | P2-P3 | P3    |
| 不太可能 | P1-P2 | P2    | P3    | P3-P4 |

经验法则：**严重程度主导**；可能性仅在邻近档位内微调，唯一例外——仅"可能"且无直接证据的 P0 降为 P1 并标注未验证。

## 报告规则

- 每项发现必须携带 `Px`、严重程度词、可能性词及一行理由（为何定该级别）。
- 报告按定级降序（P0 → P4）排列，同级按可能性降序。
- 每项 P0/P1 发现必须包含：适用法律/条文、证据、所需整改、"咨询执业律师"标记。
- 未验证项定为 P3/P4、可能性"可能"，附核实动作，绝不静默提升至 P2 及以上。

## 关键术语定义

- **执法落地**：主管部门（网信办、工信部、市场监管、公安）责令整改、罚款、App 下架或移送刑事程序。
- **商店审核拒绝**：大陆应用商店或 App Store 中国区因该违规拒绝上架。
- **数据泄露暴露**：事件触发向主管部门及受影响用户的强制报告义务。
