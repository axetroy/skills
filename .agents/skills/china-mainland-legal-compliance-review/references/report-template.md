# 报告模板（合规审查报告）

## 目的

合规审查报告的强制输出结构。填写适用的章节；不得虚构发现。

## 模板

```markdown
# 中国大陆法律合规审查报告

- 审查对象: <产品 / 代码库路径 / URL>
- 审查日期: <YYYY-MM-DD>
- 审查范围: <适用的大陆法律；列出审查领域>
- 法律依据版本: <法律清单 + 版本/引用日期，如 PIPL 2021、DSL 2021、CSL 2017/2025 修订、未成年人网络保护条例 2024、数据出境安全评估办法 2024>
- 重要声明: 本报告为合规筛查与评估，不构成法律意见。重大风险事项请咨询具备资质的执业律师。未经验证事项已明确标注。

## 一、审查范围与适用性

- 产品是否面向中国大陆用户 / 是否处理大陆境内个人数据（依据参考 01 的管辖判断）。
- 运营主体注册地、服务器所在地。
- 本次审查覆盖的领域（勾选并说明理由，至少包含: 管辖与范围、个人信息保护、数据安全）。

## 二、证据来源

- 扫描脚本输出摘要: scripts/scan-project.sh <path> 的结果。
- 已阅读文件清单: 隐私政策、用户协议、LICENSE、备案/证照文件、代码关键点。
- 未经验证/用户需确认的事项清单。

## 三、执行摘要

- 总体结论: 该项目在 <领域> 存在 <数量> 项 P0/P1 风险，总体合规状态评估为 <低/中/高/严重> 风险。
- 最高优先级事项（Top 3–5）。

## 四、风险清单

按风险等级从高到低排序，每项:

| 编号 | 风险等级 | 领域         | 发现 | 法律依据                                 | 证据                       | 建议整改措施 | 状态   |
| ---- | -------- | ------------ | ---- | ---------------------------------------- | -------------------------- | ------------ | ------ |
| F1   | P1       | 个人信息保护 | ...  | 《个人信息保护法》第29条                 | 代码扫描结果/隐私政策第X条 | ...          | 未整改 |
| F2   | P2       | 算法推荐     | ...  | 《互联网信息服务算法推荐管理规定》第24条 | 产品无备案号               | ...          | 未验证 |

每项发现应包含:

- **发现**: 一句话描述。
- **风险等级**: P0–P4 + 可能性（确定/很可能/可能/不太可能），引用 risk-rating.md。
- **法律依据**: 具体条款。
- **证据**: 具体到文件/行号/扫描信号/用户提供事实。
- **整改建议**: 可执行的行动与优先级。

## 五、各领域分析

按本次审查覆盖的领域分节，每节:

1. 领域适用的法律与要求摘要。
2. 项目现状与证据。
3. 发现与评级（引用第四节的编号）。
4. 合规差距说明。

## 六、文件/证照核验清单

| 项目                                   | 状态      | 说明                         |
| -------------------------------------- | --------- | ---------------------------- |
| ICP备案号                              | 缺失/存在 | 若存在记录编号               |
| 隐私政策                               | 存在/缺失 | 是否覆盖 PIPL 第17/30条要素  |
| 用户协议                               | 存在/缺失 | 格式条款是否公平             |
| 未成年人保护规则                       | 存在/缺失 | 14岁以下是否有监护人同意流程 |
| 算法/生成式AI/深度合成备案号           | 存在/缺失 | ...                          |
| 游戏版号                               | 存在/缺失 | ...                          |
| 数据出境路径（安全评估/标准合同/认证） | 存在/缺失 | ...                          |
| 等保备案                               | 存在/缺失 | ...                          |
| 第三方SDK清单                          | 存在/缺失 | ...                          |
| LICENSE / 第三方声明                   | 存在/缺失 | ...                          |

## 七、整改优先级建议

- **立即 (P0)**: <行动>，建议停止相关功能/上线前处理。
- **短期 (P1)**: <行动>，在 <时间> 内完成。
- **中期 (P2)**: <行动>。
- **持续 (P3/P4)**: 流程化、制度化建议。

## 八、未决问题与待确认事项

- 需要用户确认的事实。
- 需要律师确认的法律解释。
- 需要更新的法条/最新监管动态（如人工智能法草案、数据出境新规）。

## 九、附录

- 扫描脚本原始输出。
- 引用法律条款原文（按需）。
```

## 填写规则

1. 只填写有证据支撑的章节；绝不填写虚构内容的表格行。
2. 每个发现行须按 risk-rating.md 定级（P0–P4 + 可能性）。
3. 每份报告必须原文保留免责声明行。
4. 报告使用与用户对话一致的语言撰写（中文对话默认中文）；法律名称保留官方中文形式，可附英文缩写。
5. 未纳入审查的领域，在第五节列"未审查"并说明理由，不得记为"合规"。
